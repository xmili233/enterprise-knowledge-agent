## 演示与实际实现

### 已经可以操作

| 前端能力 | 实现方式 |
| --- | --- |
| 新对话与本地消息存储 | assistant-ui 会话运行时、消息历史适配器与 localStorage |
| 上下浏览与知识库入口 | 同页锚点、原生滚动，文件和文件夹搜索使用本地数据 |
| 消息、发送、停止与重新查找 | assistant-ui LocalRuntime、ChatModelAdapter 与 AbortSignal |
| 文件夹与文件浏览 | 当前目录中文件与文件夹并存、统一搜索；路径返回；文档图标打开原文 |
| 查找过程、回答与依据判断 | 适配器流式输出思考、工具调用和带引用的回答；assistant-ui 的 Reasoning、ToolGroup、工具界面与 Markdown 组件渲染 |
| 引用悬停与原文定位 | 引用预览卡片；原文面板句子级高亮、相关度与逐处跳转 |
| 设计讲解 | 按需加载的 Markdown、Mermaid 与阅读目录 |
| 弹窗及选择器 | shadcn/ui，基于 Radix 的交互原语 |

### 会话框架与知识检索的分工

assistant-ui 管理前端会话、消息流、发送、取消、重新生成、复制和滚动。输入区与消息列表使用它的官方交互组件；`ThreadListPrimitive.New` 用于开始新对话，当前不展示历史列表。原文抽屉继续使用 shadcn/ui，目录不再显示分类分栏。文件夹和文档图标以 SVG 绘制，不依赖系统图标文件；不伪造文件扩展名或下载能力。

本地适配器接收本次问题，按预设场景依次输出 assistant-ui 的消息片段：思考（`reasoning`）、工具调用（`tool-call`，带参数和结果）和正文（`text`）。消息使用 `MessagePrimitive.GroupedParts` 分组：思考和工具调用合成一条可折叠的查找过程，思考交给 Reasoning，同一轮的检索和收集证据交给 ToolGroup，两个工具通过 `makeAssistantToolUI` 注册各自的界面。正文用 MarkdownText 渲染，引用编号替换为带预览的引用组件，来源汇总、依据标记和继续追问放在回答底部。

这些组件来自 assistant-ui 的组件库（通过 shadcn 安装到 `src/components/assistant-ui/`），文案和局部样式按本项目调整。所有问题统一在全部演示资料中匹配预设场景。

assistant-ui 本身不会解析文档、检索知识或判断证据是否支持结论。后续可将适配器替换为流式服务调用，保留当前交互和来源映射契约。

### 历史如何保存

会话适配器保存标题和编号；消息历史适配器保存消息、父消息编号、分支及引用元数据。首屏移除侧栏后不再提供历史浏览和删除入口；保留浏览器 localStorage 中已有数据，新对话不会清除旧记录。存储不连接云端，也不跨设备同步。

### 尚未接入

企业登录、权限同步、文件上传与解析、关键词和向量检索、重排、模型调用、答案支持度校验、真实审批或预订服务。

### 后续如何连接服务

前端需要接收可验证的数据结构：查询范围、检索进展、回答段落、证据编号，以及原文的版本和位置。让服务生成证据登记表，再由前端按编号解析引用，不接受模型自行编造来源链接。

### 阅读体验和验证

设计讲解遵循本项目集合的统一标准：连续正文、右侧目录、窄屏章节选择器、`#design/overview` 直达链接。支持遮罩关闭、Escape 和返回入口焦点；打开讲解不会清空提问。

自动化测试覆盖查找过程与资料的对应、引用摘录逐字出自原文、只引用通过阈值的证据、适配器的片段顺序与停止，以及未知问题和个人余额等分支。构建检查 TypeScript 与生产资源；浏览器验证覆盖桌面、手机、问答、停止、引用定位、浏览与问答独立性和讲解阅读。

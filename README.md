# 企业知识助手

面向企业员工的内部资料检索与问答产品。员工可以直接提问，也可以浏览企业知识库，从制度规范、财务报销、人事行政等资料中查找依据，并通过回答中的引用核对原文。

## 项目阶段

当前已初始化独立 Git 仓库，仅包含产品说明，尚未实现应用或提供在线体验。

首阶段以可交互的前端演示呈现完整使用流程，使用明确标注的虚构企业资料与预设问答。真实文档解析、检索、模型调用和企业权限系统属于后续接入范围。

## 面向用户与使用场景

- **企业员工**：查询报销条件、请假规定、审批流程和日常操作规范。
- **财务、人事与行政人员**：让员工更容易找到现行制度，减少重复解释，并明确回答的依据和适用条件。
- **制度与知识库维护人员**：按主题组织资料，区分文件版本，帮助员工定位原文。

产品首先解决“这件事应该怎么办、依据在哪里”，让员工从自然语言问题走到可核对的内部文件。

## 首页结构

首页采用上下布局：上方是 Agent 提问入口，下方是企业知识库列表。

```text
企业知识助手                                  设计讲解

┌────────────────────────────────────────────┐
│ 想了解什么？                                │
│ 输入问题，例如：出差改签费可以报销吗？        │
│                                  [提问]    │
└────────────────────────────────────────────┘

企业知识库
[全部]  [制度规范]  [财务报销]  [人事行政]

知识库名称          简介              文档数 / 更新时间
差旅与报销          差旅、费用与审批    …
员工手册            考勤、请假与福利    …
信息安全规范        账号与资料使用      …
```

### Agent 输入区

- 作为首页的主要操作入口，允许员工直接输入想要了解的问题。
- 问答默认面向全部可用知识库；指定知识库范围时，在输入区明确显示。
- 提问后进入问答状态，保留问题、查证进展和最终回答。

### 企业知识库列表

- 列表顶部提供基础分类分栏，初稿为“全部、制度规范、财务报销、人事行政”。
- 分栏用于切换列表分类，具体分类可在后续界面设计中调整。
- 每行展示一个知识库，包含名称、简介、文档数量和更新时间。
- 点击知识库后查看其中的文件与版本信息，进一步打开文件阅读原文。
- 分类浏览与问答范围分别表达，避免员工误以为切换列表分栏就自动改变了检索范围。

## 核心使用流程

1. **提出问题**：在首页输入问题，或先浏览知识库了解有哪些资料。
2. **查找依据**：展示搜索、阅读和必要的补查进展，使用简明的操作摘要。
3. **阅读回答**：给出结论、适用条件、需要确认的信息，以及支持结论的引用。
4. **核对原文**：点击引用，在原文面板中查看对应文件、版本、页码或章节与高亮片段。
5. **补充信息**：资料不足或条件不明确时，说明缺口，允许继续追问或补充资料后重新查证。

以“出差改签费可以报销吗”为例，回答需要区分公务安排变更与个人原因，保留审批条件，并让员工点开对应制度核对。所有演示制度、条件和结论均应标注为虚构示例。

## 回答与引用原则

- 检索到相关资料、引用成功关联原文、结论得到原文支持，是三个不同层次，不混用状态文案。
- 不省略决定结论的条件、例外和适用范围。
- 引用应对应具体文件版本与原文位置，不能让模型自行编造来源信息。
- 当前资料无法支持结论时，明确说明缺少什么，不用无依据的确定性回答补全。
- 真实系统需要按员工权限限定可检索资料，并管理文件生效与失效状态；前端演示不声称已经实现这些后端能力。

## 设计讲解

在页面顶部保留统一的“设计讲解”入口，以 [Muse 的设计讲解](https://github.com/xmili233/muse-canvas#设计讲解)为参考：大尺寸阅读弹窗、连续正文、右侧目录、窄屏章节选择器及章节直达链接。

讲解内容围绕员工刚刚体验的流程组织：

1. **产品与场景**：为什么采用“提问入口 + 知识库列表”的首页。
2. **资料入库**：文字提取、OCR、版面分析、分块和来源位置的保留。
3. **检索与补查**：关键词检索、语义检索、重排与 Agent 的工具调用。
4. **引用与原文**：证据编号、来源映射、原文定位，以及引用存在和结论正确的区别。
5. **能力边界**：解析错误、资料遗漏、文件过期、权限与证据不足时的处理。
6. **演示与实际实现**：清楚区分当前可操作的前端模拟和后续需要接入的服务。
